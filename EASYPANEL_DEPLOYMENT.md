# Easypanel Deployment Guide - Medusa B2B Backend

## Quick Start Checklist

### Pre-Deployment Setup

1. **Infrastructure Ready**
   - [ ] PostgreSQL database created and accessible
   - [ ] Redis instance running and accessible
   - [ ] SMTP credentials obtained
   - [ ] Domain DNS configured

2. **Repository Ready**
   - [ ] Code pushed to Git repository
   - [ ] `backend/easypanel.yml` file exists
   - [ ] `backend/Dockerfile` file exists

### Easypanel Configuration Steps

#### Step 1: Create Project
1. Login to Easypanel
2. Click "Create Project"
3. Select "Import from Git"
4. Enter repository URL
5. Select branch (usually `main`)
6. **Important**: Set root directory to `backend`

#### Step 2: Configure Build
- Dockerfile: `Dockerfile` (in backend directory)
- Build context: `backend/`
- Image: Auto-generated by Easypanel

#### Step 3: Environment Variables

Copy and configure these in Easypanel UI:

```yaml
# Core
NODE_ENV: production
STORE_CORS: https://your-storefront-domain.com
ADMIN_CORS: https://your-admin-domain.com
AUTH_CORS: https://your-admin-domain.com,https://your-storefront-domain.com

# Database
DATABASE_URL: postgres://postgres:password@host:5432/cubitstore?sslmode=disable
DB_NAME: cubitstore

# Redis
REDIS_URL: redis://default:password@host:6379

# Security (CHANGE THESE!)
JWT_SECRET: your-super-secret-jwt-key-min-32-chars
COOKIE_SECRET: your-super-secret-cookie-key-min-32-chars

# Admin
ADMIN_URL: https://your-admin-domain.com/app
MEDUSA_BACKEND_URL: https://your-admin-domain.com
DISABLE_MEDUSA_ADMIN: false
MEDUSA_WORKER_MODE: server

# Email
SMTP_HOST: smtp.your-provider.com
SMTP_PORT: 465
SMTP_SECURE: true
SMTP_USER: your-email@domain.com
SMTP_PASS: your-email-password
SMTP_FROM: your-email@domain.com

# Optional
OPENAI_API_KEY: your-key-here
AUTO_GENERATE_DESCRIPTIONS: false
```

#### Step 4: Port Configuration
- Port: `9000`
- Protocol: `HTTP`
- Public: `true`
- Path: `/`
- Secure: `true`

#### Step 5: Domain Configuration
- Add domain: `admin.yourdomain.com`
- Enable HTTPS (automatic SSL via Let's Encrypt)

#### Step 6: Resources (Recommended)
- CPU: 1 core (minimum)
- Memory: 1024 MB (1 GB) minimum
- For production: Consider 2 CPU, 2048 MB

#### Step 7: Pre-deploy Command
The `easypanel.yml` includes:
```yaml
predeploy: yarn migrations run
```

This automatically runs migrations before deployment.

### Post-Deployment Steps

#### 1. Verify Deployment
```bash
# Check health
curl https://your-admin-domain.com/health

# Should return 200 OK
```

#### 2. Create Admin User (if needed)
```bash
# Via Easypanel terminal or SSH
docker exec -it <container-name> yarn medusa user -e admin@yourdomain.com -p yourpassword -i admin
```

#### 3. Access Admin Panel
- URL: `https://your-admin-domain.com/app`
- Login with credentials created above

#### 4. Create Publishable API Key
1. Login to admin panel
2. Go to: Settings → Publishable API Keys
3. Create key for "Webshop" or "Storefront"
4. Copy key for Vercel deployment

### Common Issues & Solutions

#### Issue: Build Fails
**Solution**: 
- Check Dockerfile path is correct
- Verify all dependencies in package.json
- Check build logs for specific errors

#### Issue: Database Connection Error
**Solution**:
- Verify PostgreSQL is accessible from Easypanel server
- Check firewall rules
- Test connection string format
- Ensure database exists

#### Issue: Redis Connection Error
**Solution**:
- Verify Redis is accessible
- URL encode special characters in password (e.g., `@` → `%40`)
- Test connection manually

#### Issue: Admin Panel 404
**Solution**:
- Verify `ADMIN_URL` environment variable
- Check domain configuration
- Ensure `DISABLE_MEDUSA_ADMIN=false`

#### Issue: Migrations Fail
**Solution**:
- Run manually: `yarn medusa migrations run`
- Check database permissions
- Verify database exists

### Monitoring

#### View Logs
- Easypanel Dashboard → Your Project → Logs
- Real-time log streaming available

#### Health Checks
- Endpoint: `/health`
- Monitor for 200 OK responses

### Updating Deployment

1. Push changes to Git
2. Easypanel will detect changes (if auto-deploy enabled)
3. Or manually trigger deployment
4. Migrations run automatically via `predeploy`

### Security Best Practices

1. **Secrets Management**
   - Never commit secrets to Git
   - Use Easypanel environment variables
   - Rotate secrets regularly

2. **Database Security**
   - Restrict database access to Easypanel server IP
   - Use strong database passwords
   - Enable SSL if possible (update connection string)

3. **Redis Security**
   - Use password authentication
   - Restrict access to Easypanel server IP

4. **Application Security**
   - Use strong JWT_SECRET and COOKIE_SECRET (32+ chars)
   - Keep dependencies updated
   - Monitor logs for suspicious activity

### Backup Strategy

1. **Database Backups**
   - Set up automated PostgreSQL backups
   - Store backups securely
   - Test restoration procedures

2. **Configuration Backups**
   - Export environment variables
   - Document all configuration changes

### Scaling Considerations

For high traffic:
- Increase CPU/Memory resources
- Consider separate worker process (`MEDUSA_WORKER_MODE=worker`)
- Use connection pooling for database
- Monitor Redis memory usage

### easypanel.yml Reference

Your current `backend/easypanel.yml` should look like:

```yaml
name: cubit-store-backend
image: ${EASYPANEL_DOCKERFILE_IMAGE}
domains:
  - domain: admin.yourdomain.com
    path: /
env:
  - name: NODE_ENV
    value: production
  # ... all environment variables
ports:
  - port: 9000
    protocol: http
    public: true
    path: /
    secure: true
resources:
  cpu: 1
  memory: 1024
dockerfile: Dockerfile
predeploy: yarn migrations run
```
